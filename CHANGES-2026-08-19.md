# CPI — build notes, round 2 (19 Aug 2026)

Answers the six points of feedback on the Policy layer / Crawlers additions.
Verified against `editions/2026-08-17.csv.gz` and rendered headlessly, with
every control exercised, before packaging.

## 1. The signature cells were unreadable — fixed two ways

**Policy signatures table.** The eighteen cells now sit under a rotated header
of crawler names, aligned column-for-column, using the same idiom as the
existing exclusion matrix. Cells are wider (13px) with a hairline border so
adjacent same-colour cells separate. Every cell still carries a hover title.

**The template card.** The bare strip is gone. It is now two labelled lists —
"Explicitly blocked · 8" and "No explicit instruction · 10" — naming every one
of the eighteen crawlers with its colour swatch. Nothing to decode.

## 2. Filters and sorting, aligned with the rest of the dashboard

Uses the existing `controls()` / `sortSel()` / Clear-button pattern, and the
same `UI` state object, so behaviour matches Crawlers, Changes and Domains.

| Table | Controls |
|---|---|
| Name recognition | Text filter (crawler or vendor), role filter, 7 sorts (named, blocked-once-named, block rate, name, vendor), Clear |
| Policy signatures | 5 sorts (domains, crawlers blocked, crawlers allowed), "hide signatures that name no crawler" toggle, Clear |
| Vendor rollup | Text filter (vendor or crawler), 6 sorts (any-blocked, mean share, training-only, crawler count, name), Clear |

Empty-state rows are handled ("No crawler matches that filter").

## 3. Two defects in the split table

- The ratio cell wrapped over two lines — now `white-space: nowrap`.
- The copy said "Three vendors run both…" while showing two. Perplexity fields
  no training crawler, so it is correctly excluded from the computation but was
  wrongly included in the sentence. The count is now derived from the data and
  states the exclusion: "2 vendors run both … the other 11 field a single role
  and are excluded." The same fix was applied to "vendors field between 1 and 3
  crawlers", which is now computed from the vendor list.

## 4. Copy drift — yes, this was a real risk. Two layers now.

You were right to ask. The numbers inside sentences always interpolated from
the data, but the *characterisations* around them were written once and would
have gone stale silently.

**Layer one — the wording derives itself.** The strongest claims are now
computed at render time:

- The panel heading reads "One template, **a third** of all blocking" via a
  `fracWord()` band table. At 24% it would say "a quarter"; at 8% "a tenth".
- "domains treat them differently — **overwhelmingly** in one direction" is
  conditional on the ratio: ≥5 gives "overwhelmingly", ≥2 gives "a clear lean",
  below that "though not by much in this edition".
- "The **8** crawlers this template names are also the **8** named most often"
  runs an actual set-equality check. If they diverge it prints the opposite
  sentence — "the two are drifting apart, worth watching" — instead.
- "the distribution is extremely top-heavy" was replaced with the measured
  figure: "the top one alone covers 74.7% of them".

**Layer two — `check-copy.cjs`.** For claims that cannot be phrased that way,
19 assertions run against `dashboard.json`, each naming the sentence it guards
and where it lives. Run it any time:

```
node check-copy.cjs
```

It is wired into `sunday-run.command` immediately after `rebuild.cjs`. It does
*not* silently block the publish — the data is correct, only the wording would
be stale — it prints the failing claim and asks whether to continue.

Tested by feeding it a mutated edition: it correctly caught an AI-policy layer
grown to 40% of frame ("real but small" no longer fair), a template cohort
shrunk below the second-place signature ("most common policy that blocks
anything" no longer true), and an asymmetry ratio collapsed to 1.1 ("not an
artefact of where the line is drawn" no longer supported).

## 5. Plain-language interpretation blocks

Seven "How to read this" panels, styled distinctly (`.reading`), one per metric
block. Each says what a high number means, what a low number means, and which
comparison is the defensible one. They are data-aware where it matters — the
role-split block picks its own verdict sentence from the current ratio, and the
name-recognition block names this edition's extreme crawlers rather than
hardcoding Timpibot.

The vendor-table block is the one worth reading yourself: it says plainly that
"blocks ≥1 of its crawlers" should not be used to rank vendors, and that the
training-only column is the sentence to quote.
